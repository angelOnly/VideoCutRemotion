## 当前调用链

1. 主 Codex 读当前稿与专业技能，安排作者；作者决定自然分段、字幕阅读、视觉与声音表现。
2. 主 Codex 提交配音、作者装配计划与必要预览。Worker 生成媒体、绑定实际音频并登记冻结版本。
3. `prepare_review` 接受明确 `units/checks/evidence`，等待原媒体完成，登记检查计划；不启动模型。
4. 主 Codex 创建或续接宿主原生审片代理，调用 `assign_review_work` 记录实际代理 ID、单元及稳定请求 ID，将返回包交给该代理。
5. 审片代理实际看听并回传；主 Codex 调用 `submit_review` 保存 partial/complete。complete 仅表示本次覆盖齐全，不能代替效果结论，也不自动续派。
6. 主 Codex 根据问题交原作者返修、决定复查与复用。`read_review` 支持状态摘要与有界等待；`read_production_task.activeReviewId` 支持恢复当前计划。
7. 创作完成后选定正式渲染作业并交出 `await_runtime`，Worker 沿原清单完成技术验证、发布及回调。没有新增最终听审或人工审批门禁。

## 文件与合同

核心修改为 `review-service.ts`、`review-invalidation.ts`、服务 routes/MCP 注册、`template-renderer.ts`、`sentence-audio.ts`、`sentence-audio-assembly.ts`、`production-timeline.ts`、`scene-speech.ts` 和 `template-package.ts`。角色规则写入财经模板整理脚本。技能维护源更新于 `.agents/skills/`，由现有脚本同步至插件视图；通用模板入口改为指向唯一维护源，避免继续加载旧审片协议。

新候选插件版本 `0.1.21`，审片协议 `4`，运行指令 `template-production/13`。`prepare_review` 必须包含 units；图片用 `{renderRequestId,frame}`，视频用 `{renderRequestId,fileId}`，连续观察显式给全局半开 range。检查方法由 Codex 选择，当前连续材料接收已有视频文件；没有新增独立音频审片作业。

`assign_review_work` 的 agentId 来源标为 `coordinator_reported`，不是程序认证的原生线程身份。写入仍使用当前 Run 凭证；原生审片者遵守只读分工，由主协调保存结果。`assignmentToken` 是分派代次标识，不是审片访问凭据。旧表名为兼容历史记录而保留，不再签发独立审片凭证。

## 失败处理与代价

- 媒体等待超时继续原作业；unknown、cancelled、failed 保留真实状态，不自动重绘或再次计费。
- 分派接替要求 previousAssignmentToken 和原因，以事务保证当前负责人不被旧请求覆盖；部分观察保留，迟到结果仅历史留档。
- 相同准备、分派、提交恢复原结果；同键改输入拒绝。旧准备请求不会重新激活被替换计划。
- 文件或源码摘要变化拒绝采用，跨 Run/跨计划提交拒绝。已发现问题跨版本保留，需实际新观察与显式处置关闭；换单元、换检查目的也不能悄悄丢问题。
- 复用仅支持有原始观察的同目的同身份静帧；连续观察不自动复用。语义影响由 Codex 负责，机器字节相同不等于语义不变。
- 原生代理的容量、看听能力和响应速度仍受实际宿主约束。本次删去了独立会话池等待路径，但未做生产计时，不能承诺 Render 耗时降至某个数值。
- 新协议不在线迁移正在执行的旧 Run；已有发行绑定校验保留。后续部署需更新插件、Worker 和模板合同，再通过网页新建任务验收。
