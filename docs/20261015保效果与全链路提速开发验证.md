## 实际调用链

1. 主协调提交静帧或正式导出，服务保存原媒体作业及尝试代次。
2. `prepare_review` 验证冻结工程、确认正文、媒体摘要与时间线，建立当前唯一计划。阶段从导出前切换到成片检查时，已有会话显式重绑，旧分派不能提交到新阶段。
3. Runtime 启动审片线程；`claim_review_work` 返回检查包；`submit_review` 按检查目的累积真实观察区间，完成后原子返回下一包。没有实际看听能力仍为未完成。
4. 作者返修后再次准备计划，服务按实际变化判定失效，等价项引用原观察，不伪装成重新看过。成片容器改变时，仅在未变分镜文件或服务连续 PCM 等价证据成立时复用对应结论。
5. 正式导出已受理且无独立工作时，模型返回 `kind: await_runtime`。执行器保留连接、Run 和作者句柄，媒体终态后启动同一主线程下一轮。
6. 最终 `kind: final` → Worker 校验交付身份和技术规格 → 本版审片质量门 → 发布复制与摘要检查 → `finish` 同事务写结果和回调事件 → 原回调发送器投递网页后端。

## 失败处理与真实代价

- 部分观察与不同真实问题逐项保留；静帧不能填补听审、连续运动或声画同步的覆盖。
- 重复完成请求恢复原响应，不多领一包；下一包已撤销时明确返回不可继续使用。旧版本、旧负责人提交仅存迟到记录。
- 观察期间媒体变化会拒绝提交；发布仍重新核对当前实际文件，不能只相信模型的 `checks` 文本。
- 没有材料或观察能力时保留待检查；阻断和未处理警告不会发布。修复后由原作者产生新证据复查，不新增跳过质量门的接口。
- 审片者停止时撤销凭证并释放未完成范围；启动失败不永久占据名额，关闭等待启动与活动轮次收敛，避免关闭数据库后继续回写。
- 媒体进度不会启动模型轮次；取消直接停止，未知媒体或未知启动保留 `unknown`。同作业重试仅在原明确失败状态按原编号与快照进行。
- 等待继续占原 Run 名额。Worker 重启后，若无法证明完整子作者树恢复，保留未知，不假称作者仍在线。
- 不跨发行恢复活动 Run 或接受其工具写入；正式切换前仍须让旧任务收敛。新表增量创建，不删除旧证据。
- 技术解码记录只在本服务进程内复用，最多 256 条；重启、淘汰、字节或参数变化均重新完整验证。此记录不能替代专业看听。
- 发布检查点和回调队列保持原职责，通知失败只重发原事件，不重新调用模型、配音或渲染。

## 验证口径

### 自动验证

新增或扩展测试覆盖：

- 唯一专业源、历史完整段落、引用闭包、真实路径、发行字节与角色读取映射。
- 两个独立 Node 进程连接同一隔离 SQLite 并发领取、提交，结果不覆盖且重复请求不多领。
- HTTP 路由与真实候选 MCP 进程的凭证边界、跨 Run／跨计划拒绝、同源参数及结构化错误。
- 逐检查半开区间、部分覆盖、问题落点、事务回滚、计划阶段切换、结论复用和最终质量门。
- 独立假 App Server 进程的启动失败、取消收敛、失效凭证替换、新版忙碌续接；同版部分完成不自动空转。
- 主执行器同连接两轮、普通进度零新轮次、重复终态只续接一次、旧迟到 final 过滤、启动响应未知与分页恢复。
- 真实媒体文件的字幕音频技术约束、全局帧、PCM、快切／回退、损坏拒绝、解码复用和发布副本摘要。
- 回调 HTTP 与业务成功分离，重投沿原事件，不重新制作。

测试中的观察文字均是隔离协议夹具，不是实际作品审片结果。最终测试数量和候选发行标识在本记录末尾登记。

本机默认 FFmpeg 缺少 `libx264`、`libmp3lame`；Remotion 自带版本又不包含全部测试源滤镜。本轮在 `.candidate/optimization-test-deps/` 解包 `imageio-ffmpeg 0.6.0` 所带工具，供隔离测试使用；未改变系统安装、项目依赖或生产编码规格。
