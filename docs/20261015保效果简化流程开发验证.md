正式调用链：`prepare_review_frames → RunWork / MediaBudget → templateFrames → onSourceFrozen / onFrameReady → ReviewService.prepare → reviewId → read_review`。失败登记通过原媒体身份返回同一 `ReviewService.prepare`，继续使用已有 SQLite 幂等规则。没有新增微服务、队列、数据库或独立审片模型池。

旧的模型拆 12 帧、搬运多个编号及重复整理全部观察步骤退出整轮主流程。独立小预览、已有媒体登记和连续材料检查入口继续保留各自用途。角色合并只作为模板制作的可选职责安排，不按代理数量自动取消独立观察。

## 状态与失败处理

- `freezeState=waiting`：已受理但尚未固定版本，暂停写入待冻结工程。`frozen` 返回真实摘要后，工作副本可继续修改；指定版本不一致明确失败。
- 媒体失败保留原快照、成功图片、缺帧和诊断，不称全部完成。本版没有缺帧续绘，不能换键声称恢复。
- 媒体成功、登记失败分别保存。恢复只核验原快照与图片，避免重新绘制。登记已提交但确认丢失时仍回到原检查计划，不丢观察。
- 重复编号同输入返回原记录，不同输入返回冲突。未知媒体只查询；登记未知可幂等核验原成功媒体。取消停止后续登记。
- 默认审片摘要保留全部问题、待处置问题与异常；完整检查项、区间、观察和文件差异在 `detailsRef`。连续观察只有范围覆盖完整才计完成。
- 单元接替保留部分观察与未关闭问题，迟到结果不覆盖当前负责人；不会按固定静默时间自动重建整个审片或创作会话。

## 仍需生产对照的事项与代价

本轮完成代码、接口、技能、候选和隔离检查；未执行真实模型每版至少三次的完整制作对照、线上部署和网页两阶段验收。因此首版返修率、角色合并收益、真实无人干预推进和整片效果尚未证明，不能据组件或媒体夹具宣布全部生产目标已达成。

整轮材料入口多承担了登记状态；完整审片结果按内容保存会增加少量磁盘文件。组件覆盖稳定包装与明确状态边界，自由场面的图表布局、合法叠放和动画接管仍由作者判断。宿主日志接收时间可能有传输延迟，不足以自动得出真实模型推理时间、关键依赖或整棵代理会话可恢复范围。
