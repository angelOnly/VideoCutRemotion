## 失败边界及独立核对

1. 首次装配请求因片头资源路径不存在被拒绝，原会话修正后沿原装配请求成功；没有重配全部声音。
2. 第一次整轮静帧任务因 `diagram_1` 时间越界失败。原视觉作者修正章节边界与声音窗口后通过模板校验。
3. 第二次静帧任务报 `Visited http://localhost:3000/index.html but got no response`。原失败记录保留，随后改用两段有明确检查目的的动态预览。
4. 动态预览技术生成成功，但部分实际帧出现标题重复铺排、右侧裁切及正文/字幕缺失。审片仅记录实际单帧，不扩展为整段连续观察。
5. 制作会话交回 [production-blocker.json](validation/20261015-local-two-stage/production-blocker.json)，明确标为诊断材料、未完成正式导出。现有成功交付校验拒绝该诊断文件，Runtime 最终为 `failed / DELIVERY_FORMAT_INVALID`，并发送失败回调；未发布异常视频。技术终态错误码与前面的视觉阻断原因分别保留，不能只看交付格式错误便遗漏实际故障。

主测试结束后，另用两个 FFmpeg 版本独立抽取原利润预览的同一局部第 62 帧（全局 2882 帧）：两个解码结果的像素和 PNG 摘要均相同，异常确实存在于该视频帧。局部第 60 帧（全局 2880 帧）则正常，因此不能用一张正常帧否定其他帧的异常，也不能断言整段持续异常。详见 [独立核对](validation/20261015-local-two-stage/frame-validation.json)、[正常帧](validation/20261015-local-two-stage/normal-frame-2880.png)和[异常帧](validation/20261015-local-two-stage/abnormal-frame-2882.png)。

源码检查未发现与重复标题直接对应的铺排逻辑，渲染、捕获或作品调用关系的底层根因尚未定位。本轮没有为此修改平台、删除校验或生成虚假的正式成片。
