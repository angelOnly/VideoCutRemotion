# 章节四路并行开发验证

## 本轮实现

Analysis 保持文字阶段。Render 输入增加 chapterWork：仅按本次确认稿的连续章节分组，保留分镜顺序，未标章节跟随上一章，跨章重复标题不合并。每组分配独立源码目录。

主协调先统一整片设计，通过宿主原生代理最多启动四位章节作者和一位统一声音作者，空闲作者立即领取下一章。共享组件、注册表和总时间线仍只有主协调写入；作者回传独立组件、纯校验器和视觉块，真实配音完成后校准再合并。分派、合并和审片恢复由协调技能执行，不宣称 Worker 自动创建代理或自动判断创作质量。

Render 会话请求五个子代理名额，使用官方配置 agents.max_concurrent_threads_per_session；实际宿主是否提供名额仍须服务器会话验证。参考：https://developers.openai.com/codex/config-reference 。

导出沿现有分镜块队列，默认四路画面并发，另一路连续音轨；每路绘图并发改为三，全局绘图预算十六，进程预算五。因此五路同时执行占十五个绘图名额，多个任务仍共用预算。不是四个章节各自重复导出整片。

财经模板 2.0.9 将纯参数校验与 React 图解注册表分开。删除校验器对画面注册表的运行时依赖；新增 visualValidators.ts，提前装配校验不再加载 React。保留原视觉注册表的组件及校验函数，由协调者登记同一纯函数。

审片者每完成一个单元保存报告，主协调及时提交部分结果；长时间无进展先检查原代理，再续接剩余范围，不重绘已生成材料，不自动判通过。

## 调用链与文件

- runner.prepare → chapterWorkPlan → input.json → taskInstruction → Render 协调技能 → 章节作者及声音作者 → 主协调装配与冻结。
- config → routes 中的共享 MediaBudget 和作业并发 → template-chunks 的有限队列 → 连续音轨及分镜合成。
- prepare-finance-template.py → 独立纯校验注册表 → verify-finance-template.mjs → 模板归档。
- 技能维护源为 .agents/skills/_shared/template-production/references，已通过既有脚本同步发行副本。

主要修改：chapter-work.ts、runner.ts、codex-session.ts、task-instructions.ts、config.ts、routes.ts、template-chunks.ts、财经模板整理和校验脚本、Render/审片技能。插件候选版本 0.1.25。

## 失败处理与代价

媒体任一路失败停止派发新块，等待已运行工作释放预算；已有成功结果沿原作业恢复。章节失败保留其他章节，回原作者继续，不能重开整片。总时间线和共享文件的单写者规则属于协调合同，不是操作系统文件锁。

增加章节代理会增加模型上下文开销；总耗时仍受最慢章节、配音、审片和共享机器预算影响，不能承诺四倍提速。已有服务器显式环境变量不会因默认值变化自动更新，部署时应设置 TEXTVIDEO_RENDER_CONCURRENCY=3、TEXTVIDEO_MEDIA_RUN_CONCURRENCY=4、TEXTVIDEO_MEDIA_GLOBAL_CONCURRENCY=16、TEXTVIDEO_MEDIA_PROCESS_CONCURRENCY=5。
